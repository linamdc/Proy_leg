# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Wearable Robotics course project (leg). Simulates lower-limb biomechanics with the MyoSuite `myo_sim` musculoskeletal models in MuJoCo. Code, comments and output are written in Spanish — keep that convention.

Layout that matters:
- `scripts/` — standalone analysis scripts (the real work lives here).
- `myo_sim/` — a nested clone of https://github.com/MyoHub/myo_sim (its own git repo, untracked by this one). Treat it as a third-party dependency; it has its own `CLAUDE.md`/`AGENTS.md` and `docs/wiki/` if you ever need to change it. Do not commit it into this repo.
- `modelos/old_pierna_nino/` — standalone MJCF of the child's right leg, one file per case, plus copied STL meshes and a hand-written `escena.xml` (sky/floor, included last so the floor body takes the last ids). The `pierna_nino_*.xml` files are GENERATED by `scripts/old_exportar_pierna.py` from `modelo_nino.spec_nino`; never edit them by hand, change the source and re-export.
- `data/opensim_6y/` — OpenSim gait versions (pelvis + both legs + lumped torso, 68 muscles) of Schmid et al.'s 6-year-old spine-children models, Female (21.5 kg) and Male (22.2 kg). Generated by `scripts/modelo_6y_marcha.py` from the original SimTK `.osim` (not in the repo; needs the `opensim` Python package). The Male model is the one matching P4. The `.osim` files reference meshes by name in the sibling `Geometry/` folder, so they must stay together.
  - `scripts/old_exportar_mot.py` writes `marcha_sano.mot` / `marcha_P4.mot` there, from the same CSVs as `old_marcha.py`, for viewing in the OpenSim GUI (Open Model + Load Motion).
  - In this Gait2354-style model `knee_angle` is NEGATIVE in flexion, the opposite of MyoLeg.
  - The left leg is the right one shifted 50 %, and the pelvis only translates.
  - `ALTURA_PELVIS` = 0.64 m is hand-computed from the joint offsets plus the knee spline.
  - OpenSim is not installed on this machine, so the .mot files have not been checked visually.
- `modelos/nino6y_mujoco/nino6y_marcha.xml` is the Male 6y model converted to MuJoCo. `scripts/marcha_6y.py` replays gait on it with both legs, the pelvis following Senden and the feet on the ground; `--caso pc_exo` adds `exo.agregar_exo` on both legs. This 6-year model is the one to use from now on.
  - It is produced by `scripts/convertir_6y_mujoco.py` (MyoConverter → `nino6y_marcha_cvt3.xml`) followed by `scripts/ajustar_mujoco316.py`. A copy of both lives in `modelos/nino6y_mujoco/scripts/`; keep them in sync.
  - `qpos0` is a valid pose (standing, legs extended) thanks to step 6 of `ajustar_mujoco316.py` (`hornear_acoples`). MyoConverter left every coupled slide (knee translations, moving muscle path points; 98 equalities, all slides) with a constant term a0 in its polynomial, which put the tibia at the hip in `qpos0`. The step moves each body by R·axis·a0 and subtracts a0 from the polynomial, the range and the keyframe.
  - In `marcha_6y.py` the CP cases mix P4's crouched knee with Senden's typical hip and ankle, which left the foot on tiptoe (sole −20° to −58°) through all of stance. Two stated assumptions fix it:
    - `FRACCION_TOBILLO`: the extra knee flexion Δ = max(P4 − Senden, 0) is added to ankle dorsiflexion (and/or hip flexion), so the foot keeps the healthy child's orientation to the ground. In the sagittal plane, foot pitch = hip − knee + ankle.
    - `despejar()`: the swinging foot is dorsiflexed until it is `DESPEJE_PIE` = 1.54 cm (Senden `foot.clear`) above the stance foot.
    - Residual: in the last ~6 % before heel strike, the incoming heel lands early and lifts the stance foot up to ~3 cm. The healthy case has a similar double-support artifact of up to ~6 cm, because the curves come from different children.
  - `scripts/old_dinamica_6y.py` is a dynamic simulation (option 1). A pelvis "harness" PD tracks the reference, and joint PDs act as the biological torque; muscles are disabled by setting `gainprm/biasprm[7]` = 0.
    - Two things were needed for stability and realism:
      - The PD damping goes into `dof_damping`, which `implicitfast` integrates implicitly; applied explicitly through `qfrc_applied` it diverges at dt = 1 ms.
      - Foot contact is enabled only during that leg's reference stance; otherwise the swing foot, ~1.5 cm off the ground, scuffs and carries body weight.
    - KNOWN LIMITATION, not solved: with the pelvis prescribed and the foot planted, each leg is an over-constrained closed chain. Exo assistance and knee weakness get redistributed to hip, ankle, ground and harness, so the exo results are unreliable: the biological-knee reduction swings from 0.01 to 0.29 N·m/kg depending on gains, the weak knee doesn't crouch, and stance peaks reach 3–4 N·m/kg against Lerner's 0.57.
    - Don't report its numbers as results. For the Lerner-style metric (biological = net − exo), use inverse dynamics.
  - `scripts/dinamica_inversa_6y.py` is the Lerner-style analysis (net knee moment by `mj_inverse`; biological = net − exo).
    - Inputs:
      - Kinematics: the `marcha_6y` cycle, smoothed with `ARMONICOS` Fourier harmonics.
      - GRF: Senden's measured GRF (`data/marcha/senden_3a6_lenta_fuerzas.csv` from `preparar_fuerzas_marcha.py`), applied at a CoP moving linearly heel→toe over stance (assumption). For CP the GRF is time-warped to P4's stance and keeps its healthy shape (assumption).
    - Method:
      - The knee moment includes the coupled tibia translations by virtual work.
      - Constraints, springs and dampers are disabled in the inverse (`mjDSBL_PASSIVE` no longer exists in MuJoCo 3.16; use `mjDSBL_SPRING`/`mjDSBL_DAMPER`).
    - Validation:
      - Shapes match: healthy vs Senden r = 0.81, P4 vs Lerner r = 0.95.
      - Magnitudes don't: the healthy curve is ~0.2 N·m/kg more flexor, and P4 is ~2× Lerner (peak 1.27 vs 0.57).
      - Pelvis residuals are ~65–75 % BW RMS (mean ≈ 0) because the reference pelvis path (no-slip / lowest-foot construction) implies CoM accelerations of 5–6 m/s² uncorrelated with the GRF (< 1 m/s²).
      - Report relative exo effects, not absolute magnitudes.
  - `marcha_6y.py` also has `crouch` / `crouch_exo` cases.
    - Data: Steele et al. 2010, `data/marcha/crouch_steele/` from `preparar_datos_crouch_steele.py`; default child C8, `--nino` picks another. Kinematics, GRF and CoP all come from one child (`Marcha.fuerza_suelo`), and the GRF is normalized so the mean equals body weight.
    - Its `precalcular` anchors the newest stance foot in both forward and lateral directions. Pelvis-height correction when advancing uses `eje_x[2]/eje_y[2]`; the old `pendiente` attribute no longer exists.
    - A later rewrite of this file once dropped the `exo.py` integration and the pc ankle/clearance fixes. When editing it, keep `cargar_modelo` → `exo.agregar_exo`, `FRACCION_TOBILLO` / `DESPEJE_PIE` / `despejar()` for `pc`, and torque scaling by `Marcha.masa_nino` (child without exo).
  - `dinamica_inversa_6y.py` also runs `crouch*` with the measured GRF/CoP.
    - C8 net knee moment: extensor peak 0.40 N·m/kg in early stance (5–20 %), ~0 in mid/late stance, flexor (−0.4) in terminal swing.
    - Lerner's near-constant stance profile therefore over-assists C8 after ~20 %: the biological moment turns flexor and absorption rises. This matters for sizing the exo profile.
    - Pelvis residuals stay large in RMS (~90 % BW at step transitions; mean ≈ 0). The no-slip pelvis path has velocity kinks at each new stance that the GRF doesn't reflect. Next fix: derive the pelvis path from the GRF.
  - All replays use imposed kinematics, so the exo can't change the motion in any of them: "crouch" and "crouch_exo" walk identically.
    - `crouch_exo_mejora` is a literature-based scenario, not a prediction. It applies Lerner's measured effect, +12° knee extension in stance (`MEJORA_EXTENSION`, a sin² bell, zero at contact and toe-off), with the ankle compensating by the same amount.
    - The GRF/CoP stay those of the crouched gait, so its inverse dynamics is approximate. The more extended knee naturally produces a mid-stance flexor moment, as in healthy gait, and that is not the child fighting the exo.
    - `comparar_marcha.py` shows this scenario by default (`--sin-mejora` for identical motion).
  - Muscle simulation, step 1: `scripts/musculos_6y.py`, static optimization on C8's gait.
    - Inputs: 10 leg coordinates; inverse-dynamics torques from the measured GRF; muscle moment arms and forces taken from MuJoCo (`mju_muscleGain`/`mju_muscleBias`), with coupled DOFs projected by virtual work through `matriz_acoples`.
    - Solver: `lsq_linear`, minimizing Σa² plus penalized per-coordinate reserves.
    - CP weakness scales `rect_fem`/`vas_int` so the knee-extension isometric max is 0.69 N·m/kg. The 6y model's quads give 2.16 N·m/kg, so the factor is 0.32.
    - Outputs: activations with no exo, Lerner's profile and the proposed profile.
    - Findings: knee reserves stay ~0. Hip add/rot reserves reach ~0.35–0.45 N·m/kg because of double-support GRF > 1.4 BW. `rect_fem` saturates at 51–53 % (pre-swing hip flexion).
  - Muscle simulation, step 2: `scripts/marcha_musculos_6y.py`, forward simulation.
    - Muscles get the step-1 activations (weak child, exo worn but off), advanced by 15 ms.
    - The harness holds pelvis horizontal and rotations; height is free, so the ground carries 1.00 BW.
    - Soft joint "reflex" PDs (`REFLEJO` × rigidez), implicit damping, and stance-gated foot contact.
    - Findings:
      - Open-loop activations alone are NOT stable: without a knee reflex the gait drifts 14–22°, and a fixed-activation quasi-static knee equilibrium was unstable (that approach was discarded).
      - With reflex ×0.8–2.0 the gait is stable and tracks C8 within 2.6–6.2° RMS. Lerner's stance-long profile extends the knee at mid-stance by +10.8° (×0.8, close to Lerner's measured +12°), +4.4° (×1.25, best tracking) and +1.0° (×2.0). The proposed 50 %-of-demand profile only gives +1–1.3°: it lowers effort but barely corrects posture.
      - Reflex ×0.8 with the proposed profile destabilizes swing; don't report it.
    - `comparar_marcha.py --musculos` shows the healthy child (Senden, measured replay) | C8 simulated WITHOUT the device (`dispositivo=False`: no-exo model, its own static-optimization activations) | simulated with the exo on, from `trayectoria()`.
    - Current contact/control setup:
      - Foot contact only in the reference stance, with stiffer feet (`SOLREF_PIE`).
      - Swing-leg correction × `FACTOR_OSCILACION` = 4.
      - Known limitation: the swing foot dips 1–2 cm below the floor at 75–100 %, because the simulated pelvis is ~15 mm lower than measured.
      - Tried and rejected: always-on contact (the foot scuffs and trips, 10–34° drift); contact from 75 % (the gait collapses); vertical harness support (still 9–14 mm, at the cost of 6–22 % BW); a swing knee/ankle clearance offset (made it worse).
    - Results with this setup, mid-stance extension vs exo off:
      - Corrective profile: +3.5° (intermediate control) and +2.7° (stiff). Lerner: +3.0 / +1.3°. Demand-following: +0.2 / +1.3°.
      - Soft control (×0.8) is unreliable here: exo-off tracking error is 12°.
      - Against NO device, the exo's mass costs ~2–3° of extra flexion (exo off vs none), so the net gain of the corrective profile is +0.7° (intermediate) to +3.8° (stiff) at mid-stance.
  - RECOMMENDED exo profile: `musculos_6y.perfil_correctivo`.
    - Shape: in stance it follows the demand like `perfil_propuesto`, floored at `NIVEL_APOYO` = 0.15 N·m/kg and capped at `TORQUE_NOMINAL` = 4 N·m; it is zero in early swing and ramps to `NIVEL_FINAL` = 0.05 N·m/kg from `OSC_TARDIA` = 80 %.
    - Mid-stance knee extension in the muscle simulation: +3.7° (soft control), +5.9° (intermediate, best tracking) and +1.2° (stiff). The demand-following profile gives only +1–1.3°.
    - Its cost in inverse dynamics: the child adds hamstring/flexor effort (0.12 N·m/kg) and peak absorption rises (2.43 vs 1.47 W/kg).
    - `resultados_proyecto.py` makes four figures with it: fig2 effort, fig3 sensors/state machine sending this profile, and fig4_postura from the muscle simulation.
  - Presentation scripts:
    - `scripts/comparar_marcha.py`: one MuJoCo scene with three children side by side (healthy, crouch, crouch + exo). It builds them with `MjSpec.attach_body` of `m6.spec_modelo(...)` under prefixes `n0_`/`n1_`/`n2_`, copies each sub-model's qpos by joint name, uses treadmill playback, and has a `--gif` export.
    - `scripts/resultados_proyecto.py` writes the three report figures:
      - `fig1_problema`: knee angle and moment for healthy, P4 and C8.
      - `fig2_solucion`: C8 biological knee torque and power with no exo, Lerner's profile and the proposed profile (`FRACCION_ASISTENCIA` × stance extensor demand, ≤ 6 N·m).
      - `fig3_sensores`: 500 Hz state machine on simulated sensors (FSR with noise, 14-bit encoder, encoder velocity) with 20 ms latency; it reports detection timing errors.
  - Kinematics are identical to the pre-fix model (1e-16 m), but compile-time constants computed at `qpos0` (`dof_invweight0`, `actuator_acc0`, `tendon_length0`) changed, so contact-heavy dynamics differ slightly from the old file.
- `notebooks/assets/myolegs*.xml` — copies of the leg model XMLs (they reference meshes via `meshdir=".."`, so they don't load standalone). `notebooks/rango_pierna.ipynb` is currently empty.
- `docs/`, `firmware/`, `software/src`, `software/tests` — empty placeholders.

## How the simulations work

- Models are loaded by registry name: `model, data = myo_sim.load("myolegs")` (80 muscles) or `"myolegs26"`. `myo_sim.load_spec(name)` returns the editable `MjSpec` if the model needs modifying before compiling.
- The project's subject is participant P4 of Lerner et al. 2017: 5-year-old, 1.15 m, 20.6 kg, spastic diplegic CP with crouch gait. `scripts/old_modelo_nino.py` is the single source for the child model: `cargar_nino("sano")`, `cargar_nino("pc", escenario)` / `spec_nino(...)`. Both versions have P4's size, so only the pathology differs between them.
  - The `MjSpec` is scaled uniformly: lengths ×s_L (meshes, body/geom/site/joint positions, slide ranges, the translation polynomials in the knee `mjEQ_JOINT` couplings, muscle `lengthrange`), masses ×s_M, inertias ×s_M·s_L², muscle force (`gainprm[2]`/`biasprm[2]`) ×s_M^(2/3). Body inertials are copied from the compiled adult model and made explicit.
  - Both versions first calibrate the healthy child's strength to McKay et al. 2017 (Table e-1, 3–9 y): quadriceps to 34.9 N·m and the four hamstrings to 27.0 N·m peak isometric torque. The gastrocnemii are left alone so the ankle isn't weakened.
  - `"pc"` then scales the quadriceps force so that the peak isometric knee-extension torque (seated, hip 90°) is 0.69 N·m/kg. Lerner doesn't report P4's popliteal angle or contracture, so `ESCENARIOS_PC` (sin_acortamiento / moderado / severo) are stated assumptions. The examiner torque of the popliteal test is calibrated so that the healthy child gives Senden's 14°. Then, for each scenario, bisection finds the hamstring shortening (fraction of L0) that gives the target popliteal angle. All of this lives in `calibracion()`, which is cached. Contracture is applied as the lower bound of the knee joint range. Spasticity (MAS 1+/1) is not part of the model; it belongs in the controller as a stretch reflex.
  - `old_exportar_pierna.py` builds the leg-only model by trimming the spec: it deletes the left leg, the torso, the free `root` joint (so the pelvis is fixed), the left-right contact pairs and the MyoSuite scenery. Then it adds the IMU sites and sensors, cameras and keyframes. `spec.to_xml()` output needs `_limpiar_xml`: myo_sim leaves an unnamed nested `<default>` that MuJoCo rejects on reload. After any change, check that the exported XML reproduces `cargar_nino` (muscle params, masses, `angulo_popliteo`).
  - The exoskeleton lives in `scripts/exo.py`, shared by `old_exportar_pierna.py` (MyoLeg right leg) and `marcha_6y.py` (6-year model, both legs). It holds all the constants and `agregar_exo(...)`, which takes `signo_flexion` (+1 MyoLeg, −1 OpenSim/Gait2354, where knee flexion is negative) so that positive ctrl is always extensor torque. Never re-implement the exo in a script; call this module.
    - Sensors must be on the skin or on the device, never inside the body (an earlier version put the IMUs on the bone axis). Placement:
      - `agregar_exo` adds the motor encoder site inside the motor, coaxial with the knee (`encoder_rodilla{sufijo}_pos/_vel`), and IMUs on the outer anterolateral face of each shell (`imu_muslo{sufijo}`, `imu_pierna{sufijo}`).
      - With `planta` (a list of body, name, sole point), it also adds one insole FSR touch sensor per support point (`fsr_{name}{sufijo}`). `marcha_6y` passes the four contact spheres, so the FSR sum equals the foot contact force.
      - `old_exportar_pierna.py` puts skin IMUs (capsule radius + IMU thickness) only for no-exo legs, and uses MyoLeg's own sole touch sites `r_foot`/`r_toes` as FSRs.
    - With `VISUAL = True`, the mass-bearing primitives go to `GRUPO_MASA` = 3 (hidden in the viewer). What you see are massless meshes generated in code by `_malla_concha`: closed partial-tube shells around thigh and shank, anterior straps, flat lateral and medial uprights, motor housing with accent ring, medial hinge, curved knee pad and ankle hinges. Mass and inertia are therefore unchanged (verified: exo bodies 0.678 / 0.32 kg on MyoLeg, total 24.19 kg on the 6y model). The meshes use `mjMESH_INERTIA_SHELL` so non-volumetric shells compile.
  - `_exo` variants (CP only) come from `_agregar_exo`. The exo parts are geoms in jointless child bodies `exo_muslo` (of `femur_r`) and `exo_pierna` (of `tibia_r`), so MuJoCo derives their inertia from the geoms. They are placed in the world at the extended pose and transformed into the bone frames; box orientations must be built as x, y, x×y to stay a proper rotation, because the tibia axis points down. Geom color must be set in `rgba`, since the MyoLeg default class's rgba overrides material color. Actuator `exo_rodilla` is a joint motor on `knee_angle_r` with gear −1, so positive ctrl means extensor torque in N·m, saturated at ±6. The torque-speed curve, cutoff speed, delay and state machine belong in the controller, not the XML. Motor size (Ø79 × 39.5 mm), mass (368 g) and rotor inertia come from the AK60-6 V1.1 KV140 datasheet. The rotor inertia is reflected as J·N² = 8.77e-4 kg·m² and added to the knee `armature`, so the motor body carries only its mass. The split of the remaining ≤ 0.632 kg among bars, valvas, pad and ankle piece is an assumption.
  - Joint `armature`/`damping` are already scaled by s_M·s_L² in `modelo_nino._escalar`; the knee ends at 0.0013 kg·m². The `armature="0.01"` in the exported default class is overridden per joint. Don't "fix" it by scaling again.
  - MyoLeg has no ligaments or muscle tone. With zero activation, hip adduction/rotation are almost free, and the hanging leg twists (hip rotation −20° to −35°, the adult model too) while the toes droop to the −30° limit. Any test that holds the hip must hold all three hip DOFs, not just flexion; otherwise the thigh twists into the joint limits as the knee moves (this was a bug in `old_mover_pierna.py`).
  - Gait data lives in `data/marcha/` as CSVs with `#` comment headers.
    - `senden_3a6_lenta.csv`: typical child, Senden 3–6 y slow walking (hip flex/add/rot, knee, ankle).
    - `lerner_P4.csv`: P4 knee angle without exo plus Lerner's exo torque profile in N·m. Only the knee exists for P4.
    - Plug-in Gait sign conventions match MyoLeg's (flexion, adduction, internal rotation and dorsiflexion positive).
    - `old_marcha.py` is a kinematic replay: it sets qpos (including the coupled knee DOFs) and calls `mj_forward`, with no dynamics. For CP cases it uses Senden's hip and ankle as a stated assumption, and the exo torque is only applied/displayed, so it doesn't change the motion.
    - Stride times: 0.952 s for the typical child, 1.14 s for P4.
  - The knee joint range is 0–120°, so the model can't reproduce Senden's +5° hyperextension or 148° passive flexion.
  - `torque_extensor_max` computes effective moment arms as dL/dθ with all coupled DOFs moving. The quadriceps inserts on the patella, which moves through its own coupled DOFs, so the `knee_angle` column of `actuator_moment` alone is not enough for it.
- `scripts/old_prueba_poplitea.py` does *static* analysis, not dynamic simulation: it sets `qpos` directly and calls `mj_forward`, then reads passive muscle force (activation 0) × moment arm about the knee.
  - Joint convention: `knee_angle_r = 0` is full extension, positive is flexion (0–120°); `hip_flexion_r` positive is hip flexion.
  - The MyoLeg knee has coupled DOFs (tibia/patella translations) driven by `mjEQ_JOINT` polynomial equality constraints. When setting the pose by hand, those coupled `qpos` values must be computed from the polynomial coefficients in `eq_data` — `mj_forward` won't enforce them.
  - Muscle shortening is modelled by shifting `actuator_lengthrange` down by `fraction * L0` (L0 derived from `lengthrange` and `gainprm[:2]`), so passive tension starts earlier.
  - Moment arms come from the sparse `data.actuator_moment` (use `moment_rowadr` / `moment_rownnz` / `moment_colind`).
  - Tunable parameters (`T_EXAMINADOR`, `CONDICIONES`, `ACORTADOS`, `ISQUIOTIBIALES`) are module-level constants at the top of the file.
